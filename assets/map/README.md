# Map data

## Add or move a photograph marker

For an ordinary map-record change, edit `gallery-places.js`; do not edit `gallery-map.js`.
Adding a new photograph still requires the full four-source workflow in
`.github/MAINTENANCE.md` (asset, Gallery card, map record, and translations).
Copy this record and replace its values:

```js
{
  region: "japan",               // japan | china | australia | europe
  admin: "JP-13",                // ISO 3166-2 code
  photos: ["2026-08-14-example"] // filename without .webp
}
```

- `photos` must match a Gallery image link in `gallery.qmd`.
- Put multiple photo IDs in the same array when they belong to the same administrative area.
- `admin` controls both the highlighted area and the marker position. The map reads the administrative label centre from `admin1-regions.js`, so coordinates do not need to be maintained by hand.
- Marker names are assembled automatically as `date · country · province/state · specific place` from the Gallery card and administrative data.
- Supported region keys are Japan, China, Australia, and Germany (`region: "europe"`). The page draws maps for China and Japan; Australia and Germany use shortcut buttons that open their first photograph. Adding another mapped country also requires a new map container and boundary dataset.
- The displayed photograph counts and map bounds update from this file automatically.

The file is regular JavaScript rather than fetched JSON so the built Gallery continues to work when `_site/gallery.html` is opened with `file://`.

## Boundary sources

The Gallery atlas uses two Natural Earth 1:110m GeoJSON datasets:

- `world-land.js`: `ne_110m_land.geojson`
- `world-countries.js`: `ne_110m_admin_0_countries.geojson`, with feature properties removed

It also uses a filtered Natural Earth 1:10m administrative dataset:

- `admin1-regions.js`: `ne_10m_admin_1_states_provinces.geojson`, limited to
  Japan, China, Australia, and Germany. Only the English, Chinese, and Japanese
  names, label coordinates, and ISO 3166-2 identifiers are retained.

Three Web Mercator regional images in `terrain/` come from Natural Earth's
1:50m Natural Earth I raster with land-cover colours, shaded relief, and water.
They are generated by `scripts/build-map-terrain.py` and provide a restrained
natural backdrop beneath the administrative boundaries without requiring a
remote tile service. Visited administrative areas are drawn separately in a
warm accent.

The raster source is Natural Earth I `NE1_50M_SR_W`, version 3.2.0, downloaded
from Natural Earth's official AWS distribution on 2026-08-14. Only the three
small generated regional JPEGs are stored with the site.

The vector source files were retrieved from the official
[`natural-earth-vector`](https://github.com/nvkelso/natural-earth-vector) repository
on 2026-08-14 and wrapped in a JavaScript assignment so the map also works in a
local `file://` preview. Natural Earth data is in the public domain; see its
[`terms of use`](https://www.naturalearthdata.com/about/terms-of-use/).
